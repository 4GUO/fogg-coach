# fogg-coach 页面组织与交互逻辑（2026-09-10 定稿）

> 风格基调见 `design-style.md`；本文定义信息架构、页面职责、交互规则。

## 一、信息架构

```
TabBar（4个）
├── 📋 今日 today      ← 默认落地页
├── 💬 教练 chat
├── 🌱 动态 community  ← 弱社区：打卡分享流
└── ⚙️ 我的 me         ← 统计并入 me 作为首屏分区
（计划 plan 为 today 的二级页）
```

设计逻辑：用户 90% 时间 = 打卡（today）+ 聊天（chat）；动态独立 tab 但弱形态（无评论仅点赞）；stats 属于低频回看，并入 me。

## 二、页面职责与交互

### 1. today（默认落地页）

职责：每天打开第一眼，30 秒内完成所有打卡。

结构：日期 + streak 总览条 → 按 plan 分组的配方卡片（锚点→微行为→庆祝三段式 + [✓打卡] + 连续天数）→ 底部：进入计划详情 / 和教练聊聊。

交互规则：
- **打卡两档**：
  - 轻打卡（默认）：点卡片即完成 + Shine 动画 + 微震动，乐观更新不等网络
  - 记录打卡（可选）：完成后浮出"记录一下？"→ 记录面板：文字 / 图片≤3张 / 心情 mood。记录永远可跳过，**打卡不能被记录流程拖重**
- 卡片三态：待打 / 已打（实色）/ 暂停（灰显）
- progression 命中 → "要不要升级？"底部卡片（拒绝则 7 天后再问）
- 空态：引导文案 → chat
- 提醒时间到未打卡的卡片置顶高亮

### 2. chat

职责：诊断 S1-S7、复盘 S8、解坏习惯 S9、闲聊。

- 诊断期顶部显示阶段进度条 S1-S7；执行期不显示，改显示打卡摘要一行
- 流式打字机输出（SSE），输出完成后快捷回复 chips 才出现；chips 收敛但自由输入永远可用
- S7 确认 → 全屏过渡动画（克制的仪式感）→ 跳转 plan 详情
- 续聊：session 状态在服务端，重进自动恢复断点
- 新愿望诊断入口：chat 顶部"+"；已有 active plan 时教练先确认"新增目标还是调整现有计划？"

### 3. community（动态，独立 tab）

定位：打卡记录的"可分享子集"，弱社区形态（利于个人主体审核）。

- 分享链路：记录面板 → [分享到动态] 开关（**默认关**）→ 文字过 `msgSecCheck`、图片过 `imgSecCheck` → 通过进流，违规提示"内容无法发布"可转私密
内容形态：习惯标签 + 文字 + 图片（"🌱 睡前手机放客厅 · 连续第5天"）
- 交互：仅"加油"（点赞），**无评论**（规避实时 UGC 运营成本）
- 排序：时间倒序，无算法推荐；自己的动态可删；有举报入口（审核要求）
- 审核延迟接受（图片 1~2s 等待态，展示"审核中"）

### 4. plan 详情（today 二级页）

- 配方卡片列表：锚点→微行为→庆祝（箭头图形可视化）
- 每卡：streak、扩展预告
- plan 操作：暂停 / 完成 / 重聊迭代（→chat S8）
- 历史版本折叠展示

### 5. me（统计并入为首屏分区）

- 分区一：**统计** —— plan 切换器（默认"全部"）、日历热力图（30天）、streak 当前/最长、7/30天完成率、心情曲线、每周复盘报告入口（卡片列表）
- 分区二：提醒设置（habit 级开关与时间、订阅消息授权管理）
- 分区三：计划历史（finished 归档）
- 分区四：关于 / AI 生成内容合规声明

## 三、核心流转

```
新用户 → today(空态) → chat 诊断 S1→S7 → plan 生成 → today 打卡
每日循环：打卡(轻/记录) → Shine → (命中升级提示) → (可选分享→机审→动态流)
周循环：review_day → 后端生成报告 → me/stats 报告入口 → 携报告进 chat S8 → 迭代
随时：chat 主动复盘 / S9 / 新愿望新诊断；community 浏览/加油
```

## 四、贯穿原则

1. 打卡永远优先：任何功能不得加长"打开→打卡"路径
2. 庆祝不等网络，动画本地即时触发
3. 记录与分享永远可选、默认轻量
4. 阶段进度条是诊断期的动力装置
5. 中性克制：无红点轰炸、无连环推送
