# fogg-coach 产品定稿（v1.0）

> 2026-09-10 方案讨论定稿汇总。实现以此为准，细节见引用文档。
> 代码代号 fogg-coach；对用户展示名配置化（提审前定）。

---

## 1. 产品定位

**AI 福格行为教练小程序**：用户与教练 Agent 对话诊断，生成个人微习惯计划；小程序承载每日打卡、即时庆祝、数据回流与迭代闭环。

```
愿望 → 对话诊断(B=MAP) → 微习惯配方计划 → 每日提醒/打卡/庆祝 → 数据回流 → 复盘迭代
```

- 目标用户：屡败于意志力、想养成习惯的普通人
- 方法论：BJ Fogg《福格行为模型 / Tiny Habits》（docs/fogg-method.md）
- 核心信念：**失败 = 设计问题，不是意志力问题**

## 2. 设计理念（四条根原则）

1. **中性克制**：克制、干净、平视感。不哄小孩、不逼内卷，安静的执行陪伴工具（docs/design-style.md）
2. **打卡永远最轻**：任何功能不得加长"打开→打卡"路径；记录与分享永远可选、默认轻量
3. **不信任 LLM 自律**：状态机在服务端，LLM 只做单步生成与判定；推进权、跳步防护、默认值兜底全在后端
4. **社区做榜样感不做热闹感**：让用户看到优秀的人、感受优秀的氛围；优秀=坚持、真实、具体，不=鸡汤、炫耀、完美主义（docs/community-roadmap.md）

## 3. 关键技术决策（全部已拍板）

| # | 决策 |
|---|------|
| LLM | GLM-5.2 + DeepSeek 双 Provider（OpenAI 兼容抽象，可按用途路由/热切） |
| 主体 | 个人主体；类目 教育>学习辅导 / 工具；合规约束写入 prompt（无治疗/诊断表述） |
| 命名 | 中文名挂起到提审前；展示名配置化 |
| 阶段推进 | 尾标记 `[STAGE:DONE/HOLD/SKIP]` + `[QUICK:...]` chips；后端白名单顺序推进；S7 后端主动触发 |
| 改愿望 | `[RESET_WISH]` 回退 S2（不重走 S1）；context 标 superseded 保留；每 session ≤2 次 |
| 计划 | 多 plan 并存不锁单；active ≥3 教练软性引导收敛 |
| 复盘/解坏 | S8 双通道（主动聊天 + review_day 异步静态报告）；S9 仅用户主动 `[MODE:UNDO]`，不自动推荐 |
| 富媒体打卡 | 文字 + 图片≤3 + 心情（语音已砍）；存储本地磁盘，MVP 不上 OSS |
| 团队打卡 | 私人/团队两模式；打卡圈=共同目标+各自配方+互见流；邀请制 ≤10 人；仅点赞；排 v2 |

## 4. 页面组织

```
TabBar 4 个
├── 📋 今日 today   ← 默认落地，30秒完成打卡
├── 💬 教练 chat
├── 🌱 动态 community
└── ⚙️ 我的 me      ← 统计并入首屏分区
（plan 为 today 二级页；v2 增圈子二级页）
```

设计逻辑：90% 用户时间 = 打卡 + 聊天；动态独立 tab 但弱形态；stats 低频回看并入 me。

## 5. 交互设计要点

### today
- 按 plan 分组配方卡（锚点→微行为→庆祝三段式）
- **两档打卡**：轻打卡=点击即完成+Shine（200ms 内本地触发+微震动，乐观更新不等网络）；记录打卡=可选面板（文字/图片/mood），可跳过
- progression 命中弹"要不要升级？"（拒绝 7 天后再问）
- 提醒时刻到未打卡卡片置顶高亮；空态引导进 chat

### chat
- 诊断期顶部 S1-S7 阶段进度条（动力装置）；执行期改显打卡摘要
- 流式打字机（SSE chunked）；chips 收敛但自由输入永远可用
- S7 确认 → 克制的全屏过渡 → plan 详情（仪式感时刻）
- 服务端存 session，重进自动恢复断点

### community
- 分享默认关，主动开启 → 全量机审（msgSecCheck/imgSecCheck）→ 进流
- 仅"加油"点赞，无评论；时间倒序无推荐；可删可举报
- 演进三档：MVP 薄社区 → 今日话题/加油通知/教练精选（榜样位）→ 好友流/战报广场/里程碑分享卡

### plan（二级页）
- 配方卡 + streak + 扩展预告；操作：暂停/完成/重聊迭代(→S8)；历史版本折叠

### me
- 统计（plan 切换器/热力图/streak/完成率/心情曲线/复盘报告入口）
- 提醒设置、计划历史、AI 内容合规声明

## 6. 教练人格（写进 base prompt）

- 称呼只用"你"；emoji 仅打卡场景一个 🌱
- 平实、笃定、简短（≤150字）；专业教练感，非闺蜜感
- 肯定不吹捧："连续 7 天了" > "太棒啦！！！"
- 归因铁律：失败永远谈设计不谈意志力
- 合规铁律：习惯养成工具定位，无医疗心理治疗表述

## 7. 视觉规范（摘要，详见 design-style.md）

- 白/浅灰底，深灰文字，单一低饱和强调色（靛蓝 #4C6EF5 或墨绿 #2F9E6E，实现时定）
- 中等圆角 8-12px，线性图标，无手绘插画
- Shine：粒子光效/波纹 + "你做到了"；里程碑一次性数字动画；无红点轰炸、无连环推送

## 8. 数据模型（核心表）

```sql
users / sessions(stage, context JSON) / messages
plans(status active|paused|finished, version) / checkins(mood, media JSON, group_id NULL)
posts(社区动态, status pending|pass|reject)
groups / group_members        -- v2 仅留口子
```

## 9. 里程碑

| 阶段 | 内容 | 验证标准 |
|------|------|---------|
| M1 | 专家 prompt + 后端 /chat /plan（GLM-5.2/DeepSeek 双接） | curl 走完 S1-S7 出合法 plan JSON（3 愿望测试） |
| M2 | 小程序 chat + plan + today | 手机完整"聊→生成→看到计划" |
| M3 | 打卡两档 + 富媒体 + Shine + 统计 + 订阅提醒 + **社区动态+机审** | 连续 3 天自用打卡，动画秒级 |
| M4 | S8 复盘 + S9 解坏 + 打磨 | 提审上线 |
| v2 | 团队打卡（打卡圈） | 已定稿不排期 |

## 10. 风险与护栏

| 风险 | 对策 |
|------|------|
| LLM 跑偏 | 三道防线：分阶段 prompt / 尾标记校验 / 按钮事件绕过 LLM |
| 个人主体 AI 审核趋严 | 教育工具类目 + 合规 prompt + 弱社区形态（无评论、全量机审）+ chat 降级表单的退路 |
| 订阅消息一次性授权 | 打卡后引导重订；降级应用内提醒 |
| 诊断成瘾从不执行 | RESET ≤2 次；active plan ≥3 软收敛 |
| 社区攀比倾向 | 监测删记录率，先调文案不加功能 |
