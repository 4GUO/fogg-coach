## [B1] 刁钻: 直接给我完整健身计划

**用户:** 直接给我完整健身计划

**教练输出:**

```
用户想跳过流程直接要计划。根据规范，这是“跳跃型”用户，处理方式是：顺从 + 用最小信息（通用锚点）出糙计划，绝不拦。

我应该：
1. 顺从情绪，给一个基于通用锚点的糙计划
2. 不拦用户，但可以自然带一句后续可优化
3. 输出格式：纯文本，结尾带问题或等待
4. 这算阶段信息收集吗？用户没提供任何信息，我给的是通用计划。S2 的推进条件是 motivation + ability_gaps≥2 + anchors_found≥2，都没收集到。但规范说“信息不足用默认值补，永远让用户能拿到计划离开”。

所以我应该用默认值补齐：通用锚点（刷牙后、午饭后、睡前），给出微习惯式的极小健身计划。

注意：微行为必须30秒内可完成。所以“健身计划”要落地成微习惯版本，比如“刷牙后做2个深蹲”。

回复要简短（≤150字），口语化，结尾带问题。给的糙计划要符合微习惯原则，用通用锚点。

草稿：
“好，先给你一版最简的，不合适随时改：

起床关闹钟后 → 做2个深蹲
午饭后刷完碗 → 靠墙站30秒
睡前刷牙后 → 平板支撑10秒

每个都30秒内完成，别加量。先跑3天，遇到卡壳的地方告诉我，我帮你调。

先试哪个？”

字数检查：大约120字左右，符合。结尾有问题。不需要[STAGE:DONE]因为S2信息没收集齐，但这算给了糙计划。要不要输出标记？推进条件没满足，不输出[DONE]。 QUICK按钮可以给：先试第一个/全都试/还是聊聊我的情况。

其实更好的做法是给一个按钮引导回流程，但规范说绝不拦。可以在末尾自然问一句。加个[QUICK:先跑3天再说|先聊聊我的情况]。好，行。这版给你，先跑起来——

1. 起床关掉闹钟后，做 2 个深蹲
2. 午饭放下筷子后，靠墙站 30 秒
3. 晚上刷完牙后，平板支撑 10 秒

每个都是 30 秒内搞定，锚的全是你每天必做的事，不用靠提醒。别加量，先跑 3 天。

卡在哪儿随时告诉我，我帮你调。也可以现在花一分钟说说你的情况，我把计划改得更贴你。

[QUICK:先跑3天再说|先说说我的情况]
```
